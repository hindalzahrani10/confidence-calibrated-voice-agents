# NM-VoI methodological quality-control audit

Scope: code, logged dev episodes (`data/phase5/dev.v1`, train+val only) and stored artifacts. **Nothing was re-run** (no ASR, TTS, policy, tuning or dataset step); the held-out test episodes were not opened. The only things executed were `scripts/test_nmvoi.py` (unit/leakage tests, passes) and the read-only `scripts/build_review_package.py`, which wrote only under `reports/audit/`. Numbers below come from `reports/audit/audit_stats.json`. I did not rely on the earlier report; each verdict cites code. Data are synthetic; Phase 1 annotations are unreviewed (AI-drafted).

## 1. Requirement-by-requirement verdicts

| # | Requirement | Verdict |
|---|---|---|
| 1 | Belief update after a noisy reply, utility vs true intent, no ground truth to the policy | **Satisfied** (with caveats a–d) |
| 2 | One-step lookahead, explicitly documented | **Satisfied in code/formulation; partially documented in the report** |
| 3 | Replies really pass TTS → noise → ASR | **Satisfied** |
| 4 | Channel estimated on training data, by SNR and question type, no val/test leakage | **Satisfied for estimation; evaluation caveat (in-sample dev)** |
| 5 | Replies relevant to the question actually asked | **Partially satisfied** |
| 6 | Baseline fairness | **Partially satisfied** |
| 7 | Lexical belief distinguished from the intended 7–8B LLM | **Satisfied** (one wording caveat) |

### 1. Belief update, utility, no ground-truth exposure: Satisfied
- Agent inputs are only ASR words of the initial clip and a blind SNR bucket from samples (`scripts/run_episodes.py:99-103,109-114`). The prior comes from `BeliefModel.posterior` (`src/ontology.py`), then `pol.decide(AgentState(cat, b0, bucket))` (`src/nmvoi.py:147-152,228-240`).
- After asking, the simulator reply goes through `ReplyService` and the agent sees only `rr["text"]/rr["words"]` (`run_episodes.py:135-147`). The outcome is parsed agent-side (`parse_confirm`/`parse_closed`/open combined scoring, `run_episodes.py:148-161`, `src/channel.py:32-57`). The belief is updated by Bayes with the same channel matrix the policy used to plan (`nmvoi.py:99-123,139-142`; `run_episodes.py:146,162-163`). The final action is chosen from the updated belief (`pol.final(b)`, `run_episodes.py:174-177`).
- Utility is computed evaluator-side against `acceptable_tasks` via `accepted_mask` (`run_episodes.py:94,178-188`; `src/evalutil.py:42`). The agent-side AST scan in `scripts/test_nmvoi.py` passes (re-run today): no identifier/string containing "hidden"/"private" in agent modules.
- Caveats: (a) correctness is "in the acceptable set" (wildcard patterns such as `slots: {…: "*"}`), not equality to one gold task; (b) when a reply is unparseable the belief is silently left unchanged and the policy still pays the cost (19/108 nm_voi asks, 17.6%); (c) the corrective-"no" path adds extra lexical evidence outside the channel model, with the fitted β and no channel discount (`run_episodes.py:164-171`) and applies to every policy, including those that otherwise assume a perfect channel; (d) the open-reply gate `max S_r > 0.5` and `M_SUPPORT=8`, `accept=0.6`, `prior_strength=4` are hand-set constants, not config values (contrary to the CLAUDE.md "config over constants" convention), and I cannot show from artifacts how they were chosen. **Label-space leakage** is separate and shared by all policies: the catalogue always contains the gold task (stated in the report, but the AST scan cannot detect it).

### 2. One-step lookahead: Satisfied in code; documentation gap
- `src/nmvoi.py:1-8` states it; `notes/Formulation.md:42-43` fixes "one-step lookahead decision horizon". `eu_ask` (`nmvoi.py:126-136`) values a single question then answer/abstain; `run_episode` allows exactly one question (`turns ≤ 1`). A failed or "none of those" reply cannot trigger a second question.
- Gap: `reports/nmvoi_experimental_report.md` says "one-step expected utility" in passing but does not list single-question/no-re-ask as an assumption or a limitation, and it matters here (17.6% of asks are wasted with no recourse). I did not edit the report.

### 3. Noisy clarification channel: Satisfied
- Replies are never given to the agent as clean text. Text → `ReplyService.get` maps to a deterministic clip id (`src/audio_service.py:101-132`); Phase 2 inventory clips or logged on-demand ones are produced by Piper TTS then `B.noisy(...)` mixing at the target SNR from the split's own noise partition, then faster-whisper (`scripts/generate_ondemand.py:35-54`, identical code to Phase 2). The agent then only sees the transcript/word probabilities.
- Verified on all 108 nm_voi dev asks: 58 reply clips from the Phase 2 inventory + 50 on-demand; **all 108 have an existing audio file and an ASR record** (`audit_stats.json: nm_voi_reply_provenance`). The 20 dialogues in the review package were also sha256-checked against manifests (no F12 flags). Reply ASR equals the intended text in 90/108 asks (83%).
- Notes: one noise draw per reply clip (no replicates); the reply is conditioned on the initial clip's nominal SNR and the agent does not re-estimate SNR on the reply; clean-condition replies are TTS+ASR without noise (as intended).

### 4. Channel estimation: Satisfied for leakage, with an evaluation caveat
- `scripts/estimate_channel.py:90-94` fits the table from `collect({"train"})` only; val counts are computed separately for a check and not used (`:91,104-105`); `channel.v1.json` records `fit_on: train`. Train reply clips all use the train noise partition (414/414) and val clips the val partition (138/138). Cells are keyed by question type (confirm_yes, confirm_no, closed, open) × nominal SNR bucket (`src/channel.py:87-109`); total 624 trials, i.e. 22–60 per cell. The blind-estimated bucket is used at decision time (99% accurate on dev, 1 of 160 mislabeled).
- Caveats: (i) **dev results pool train+val, so for the 30 train items the channel table, β and the SNR centroids were fitted on the same items** (in-sample); only 10 val items (and 10 test) are out-of-sample. Val-only utility (40 episodes): nm_voi 0.653, noise_indep 0.660, **evpi 0.740**, confidence_threshold 0.350, always_ask 0.250, never_ask 0.000. This agrees in direction with the pooled dev table but the pooled intervals are partly in-sample. (ii) The table is estimated from scripted Phase 1 probe replies, whereas closed-loop replies use options the agent chose; the two distributions differ. (iii) Cells pool bare+corrective "no" and select+"none of these"; the open cell depends on the lexical belief. (iv) `src/ontology.py` hash (125213c4cf792c4b) equals the grammar hash recorded in `calibration.v1.json`, so the grammar was unchanged after the β fit.

### 5. Closed-loop consistency: Partially satisfied
- Satisfied by construction: `UserSimulator.reply` (`src/simulator.py:57-82`) branches on the question actually asked. Across nm_voi dev asks, question/reply type pairs are only compatible ones (`closed/select 55, closed/none_of_these 1, confirm/yes 30, confirm/no_bare 3, open/answer 19`); there were zero off-target replies and zero type mismatches (F4/F5).
- Not established (needs your listening/reading): (a) **open replies are Phase 1 fragments written for specific probe questions** ("Jazz", "Dan", "The dentist appointment", "Seven in the morning") but are given in response to the generic prompt "Could you tell me more precisely what you want?" Whether a fragment answers that prompt naturally is a judgment call. (b) The "No" branch of confirmation is barely exercised (3 of 33 confirm asks) and "None of those" once in 56 closed asks, so those channel paths are almost untested in closed loop. (c) The simulated user is deterministic, never mishears, hesitates or contradicts itself. (d) Replies are single fixed strings; every SNR condition of an item receives the same text.
- Detected: 19 of 108 replies were unusable (F2). 8 of these are two items (`p1_underspec_01`, `p1_underspec_09`) that fail at all four SNR levels including clean, e.g. "Seven in the morning" is transcribed "7 in the morning." and not parsed. These are parser/normalisation limits unrelated to noise, but they lower the measured channel reliability and can masquerade as noise effects.

### 6. Baseline fairness: Partially satisfied
- Fair: all policies share the same `BeliefModel` posterior, β (except the deliberate `abl_uncalibrated`), tie-break key, blind SNR bucket, simulator, reply service and utility (`run_episodes.py:106-188`, `make_policies:51-71`). `evpi`, `noise_indep_voi`, `nm_voi` differ only in channel `mode` ("perfect"/"pooled"/"snr") in both planning and update.
- Not fully fair: (i) the threshold baselines and `always_ask` can only ask one closed question about the max-entropy variable and can never abstain (`nmvoi.py:177-205`, `Policy.final`); the VoI family also has open/confirm questions and abstention. The VoI-vs-threshold utility gap therefore mixes decision rule with action space; the ablations (`abl_*`) isolate parts of this but there is no threshold policy with abstention or with the confirm question. (ii) The thresholds are tuned on 10 val items while the dev pool includes val (in-sample for them; val-only 0.350 vs pooled 0.602), whereas VoI uses a-priori costs. (iii) Baselines update at face value after a reply (`getattr(pol,"mode","perfect")`), consistent with "no channel model" but it means they treat "None of those" etc. as certain. (iv) Initial-belief ties are broken by the same hash jitter for all policies, so tie outcomes are shared, not independent.

### 7. Lexical model vs intended LLM: Satisfied
- `configs/default.yaml:30` still names the intended `Qwen/Qwen2.5-7B-Instruct`; it was **never run** (2 vCPU, 3.8 GB, no GPU). The implemented belief is `BeliefModel` in `src/ontology.py`: a word-overlap scoring of 185 catalogue tasks against the ASR transcript with one fitted softmax temperature. It is not a language model, it has no semantic understanding, and its probabilities are "calibrated" only in the sense of one temperature scalar on train. The report states "No LLM is possible" (line 14) and never calls it an LLM. Wording caveat: the report's "calibrated belief" and the "calibrated expected-utility" conclusion should be read as lexical-model temperature scaling, not LLM confidence calibration (the original research question about confidence signals from an LLM is untested).

## 2. Additional findings (not in your list)

1. **Half of the initial beliefs are exact ties.** 82/160 nm_voi dev episodes have the top two tasks within 1e-3, broken by a hash jitter (`ontology.py`). 72/82 are intent or underspecified items, i.e. designed ambiguity (e.g. `play some jazz` vs `play some classical`, 0.1634 each). But 8 are `none`-category items that should be unambiguous, e.g. `p1_none_11` ("…saying I'm running late" ties with "…saying running late", 0.4987 each) and `p1_none_10` (ASR "9 p.m." ties "9 pm" and "9 am", 0.4998 each). Cause not diagnosed. These look like lexical blind spots that create artefactual ambiguity, and they drive asks and wrong answers unrelated to acoustics.
2. **Many clarifications are near-indifferent.** Median EU margin between the chosen action and the runner-up is 0.10; 6.9% of nm_voi decisions are within 0.02 and 10.6% within 0.05. Example D02: ask_confirm EU 0.8934 vs answer 0.8899. Under these margins, small channel changes can flip actions but rarely matter.
3. **nm_voi and noise_indep_voi are nearly the same policy on this data.** They choose a different first action in 5/160 dev clips (SNR 20:3, 10:1, 5:1) and **0/160 differ in the final answer/abstain outcome**; the 5 utility differences are cost-only. The mean difference (−0.004) is therefore a cost artefact of slightly more asks, not a decision-quality difference.
4. Unnecessary-clarification rate (0.34 for nm_voi) is partly caused by item 1, which also applies to `none` items.

## 3. Limitations that matter for the central hypothesis (noise-dependent vs noise-independent VoI)

**Is there enough acoustic variation to separate the policies? No, not on this evidence.**
- ASR WER on initial utterances moves from 3.0% (clean) to 9.0% (5 dB). The estimated channel is flat within sampling error: clean vs 5 dB, Fisher exact p = 1.00 (confirm-yes 30/30 vs 30/30), 0.72 (confirm-no 55/60 vs 57/60), 0.43 (closed 42/44 vs 39/44), 0.41 (open 20/22 vs 17/22). The pooled rate is within a few points of every bucket rate, so `snr` and `pooled` channels give nearly the same EUs.
- One TTS voice (clear, studio-like), one real noise recording with an artificial lead-in/tail, 5 dB as the worst case, single noise draw per clip, replies are short and fixed. Real conditions that actually stress ASR (accents, reverberation, 0 dB and below, babble, far-field, disfluency) are absent.
- Smallest relevant effect: with 22–60 trials per cell, only drops of roughly 20+ points between SNR levels would be detectable; the present differences (0–14 points) are inside that.
- The benefit of NM-VoI also needs decision boundaries that fall between the channel values; given the near-tie beliefs and the ties noted above, many decisions are governed by the belief, not the channel.
- Stronger structural caveats: lexical belief (not LLM), catalogue contains gold, 40-item dev and 10-item test, unreviewed AI-drafted annotations, in-sample dev.

**Experiments that would be scientifically justified (to run only after your review; none was run or started):**
1. A pre-registered power analysis, then a larger condition range chosen to produce a measurable channel drop (e.g. SNR below 5 dB, multiple noise types, multiple voices, accents/real recordings, reply replicates), with channel reliability reported before looking at policy performance. If the channel stays flat, report that as a negative result for NM-VoI.
2. Re-estimate the channel from closed-loop replies (the replies actually generated per question) rather than scripted probes, and evaluate only out-of-sample items (cross-validation over items) so train items are never scored with their own channel.
3. Fix or at least quantify the lexical/parsing artefacts (ties on `none` items, "7 in the morning" style failures) as a model-limitation analysis, then check whether the nm_voi vs noise_indep_voi comparison changes; do not tune on test.
4. Give the threshold baselines the same action space (abstention, confirm/open questions) so decision rule and action set are not confounded.
5. Sensitivity sweeps stated in advance: cost scales, abstention reward, reply style (bare vs corrective), a user simulator with realistic errors.
6. If feasible with approval and no spend beyond the existing machine: an LLM belief model. That requires hardware not available here; it is not proposed as an action.
7. Human review of the Phase 1 annotations (deferred) before any claim about validity.

Negative or null results on the NM-VoI vs noise-independent comparison are valid findings and should be reported as such.
